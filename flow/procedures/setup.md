# Setup procedure

## Inputs

Requested onboarding/repair scope, current repo/harness inventory, provider catalog
and existing spec root or explicit scaffolding request.

## Prerequisites

Audit read-only first. Report present/missing components, discovered sources,
shadowing, hook configuration and actual verification separately. Do not install
components or change user profiles merely because they are absent.

## Artifacts

For explicitly requested spec scaffolding, call existing Spec setup. For a harness
repair, present exact affected paths and preserve owned/user boundaries. Route
non-Quick product or setup mutation through feature planning and approval;
legacy `setup.apply` is not blanket permission. Preserve cursor/receipts before
replacing discovery. Never rewrite third-party caches or clobber user prose.

## Checks

Check installed resource loading and relative links, idempotent retry, legacy
runtime preservation, collisions and uninstall ownership. Run existing doctor
and affected adapter checks. Configuration presence alone does not prove host
activation or authenticated blocking. Report available capabilities honestly.

## Recovery

Preserve conflicting copies and report the remediation. Interrupted migration
retries from preserved runtime data; it does not reset to idle or delete foreign
files. Follow [compatibility](../reference/compatibility.md) for unsupported hosts.

## Example

A repo has an old workflow named `vibe` with a live cursor. Preserve its data,
install `flow`, update owned callers, then install the root toolkit guide. Leave
a foreign `flow` skill intact and report the collision instead of overwriting it.
