# Strategy procedure

## Inputs

Direction question, discovered spec root, relevant lessons and current decisions.

## Prerequisites

Read the relevant hubs and linked notes. Use bounded brainstorming to clarify
outcomes and constraints. Strategy is planning/knowledge work; it grants no
implementation permission. A worker uses its supplied brief instead of rerouting.

## Artifacts

Ask Spec to record approved durable decisions in its owning artifacts. Keep the
knowledge current and link evidence. A proposed implementation enters feature
design/plan with explicit scope and checks. Do not start coding from agreement
with a strategy discussion.

## Checks

Run existing Spec validation for changed artifacts. Review decision consistency
and concrete unresolved questions. Keep implementation status separate from a
validated document. Do not advertise deferred capabilities as available.

## Recovery

Unclear direction returns to clarification. Missing root/binary uses explicit
Spec setup/remediation. A new behavior request enters feature planning and its
human approval gate. Preserve existing artifacts during recovery.

## Example

“Prefer offline exports” can become a durable decision. “Build offline exports”
then needs a concrete feature design and plan before implementation approval.
