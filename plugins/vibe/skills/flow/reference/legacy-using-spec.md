# using-spec

If there is even a 1 % chance the work changes behaviour, structure, or docs, invoke the `spec` skill BEFORE any other action, including clarifying questions.

| Work | Route |
|---|---|
| New feature or design | `spec` feature flow |
| Fix, refactor, or doc change | `spec` quick-fix row |
| Spec or `docs/superpowers` edit | `spec` first |

Spec decides *where* work is recorded; superpowers process skills decide *how* feature work is designed; if superpowers is absent, the spec fallback applies.

| Thought | Reality |
|---|---|
| "Just a quick change" | Quick changes route too. |
| "I'll check files first" | Route first; the skill tells you which files. |
| "The spec is out of date anyway" | Then the route includes fixing it. |
