- **D48 — Global store and harness projection (v0.5, row C0).** `vibe` keeps one user-level store (`~/.config/vibe/`: root `AGENTS.md`, `mcp.json`, `skills/`, `store.json`) and projects it into Claude Code, Codex, OpenCode and Factory droid. `vibe install` registers one user-level SessionStart hook entry per harness; `vibe sync` and the hook project the store into each harness's own files. Design: [global-store design](../../superpowers/specs/2026-10-23-global-store-design.md); tech: [cli-store.md](../tech/cli/cli-store.md).
  - **Hooks (D25 amended).** The front door is a fourth, user-level hook owner, beside spec, flow and instruct. Its only duty is SessionStart projection. The hook prints at most one line: a stdout notice (for Claude, Codex and Factory a `{"systemMessage":"vibe: …"}` JSON line the harness shows the user; plain text for OpenCode), or a stderr skip cause. The stale-Claude-MCP reminder repeats every session until `vibe sync` runs. It never injects instruction content (instructions reach harnesses through files), never spawns a subprocess or touches the network, and always exits 0.
  - **Plugin (D40 amended).** The vibe plugin still carries no hook: vibe registers no plugin hook. It merges one user-level entry per harness into that harness's global hooks file (`settings.json` for Claude, `hooks.json` for Codex and Factory); OpenCode gets a plugin file whose setup spawns the hook. Third-party hook entries survive install, sync and uninstall.
  - **Local only (D42, D43).** Projection is local, from the store to the harness files. It is not source sync and not a git fetch: no network code. D43's git-sourced blocks stay with `vibe-instruct`.
  - **Ownership.** `state.json` (`$VIBE_STATE`, else XDG state, else `~/.local/state/vibe`) records what vibe owns: `v`, `store_hash` (may be empty after a partial failure), `mcp_hash`, `targets` keyed `claude:instructions`, `codex:instructions`, `codex:mcp`, `droid:instructions`, `droid:mcp` (each `{hash}`), and `owned.{mcp,hooks,plugins,links,created}`. It is both the skip cache and the uninstall record. Anything not recorded, or outside a `vibe:store` marker block, is never changed. A same-named entry vibe does not own wins and is reported as kept. A symlinked target file is refused.
  - **Secrets.** vibe never writes a secret it detects on import. `store import-mcp` replaces likely secrets with placeholders and prints variable names only: `${VIBE_<SERVER>_<FIELD>}` for headers and URL query values, and `${K}` (the key's own name, so Codex `env_vars` can forward it) for an env secret of key `K` unless another field already uses `${K}` for a different purpose; `--keep-literals` opts out with a warning. URL userinfo is never rewritten and always warns. Literals the user writes into `mcp.json` are projected as written, with a one-line note per server.
  - **Global root.** `VIBE_STORE` overrides the whole global root (default `~/.config/vibe`), including what C1–C6 keep there (`repos.json`, `spec/lessons.md`, `instruct/`).
  - **Known limits.** A disabled harness keeps its old projection until `vibe uninstall`. `markers::remove` returns text that lacked a trailing newline with one (remove after upsert is a 1-byte diff on such files). Empty or missing store `AGENTS.md` (instructions `None`) leaves existing harness blocks untouched; uninstall removes them. Windows skills links are skipped with an Info note. A Codex `config.toml` with a root inline `mcp_servers = {…}` gets no vibe MCP block (an existing vibe block is removed with a note). Claude MCP is projected only by `vibe sync` (the CLI call); the hook prints a notice instead. Factory `mcp.json` is re-serialised with 2-space indentation when anything changes.
