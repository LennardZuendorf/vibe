- **D50 — Unit-row forms are artifact-scoped, and no rows is an answer.** Ruling on [#133](https://github.com/LennardZuendorf/vibe/issues/133), answering the empty-vs-unreadable question the feature lifecycle contract ([#126](https://github.com/LennardZuendorf/vibe/issues/126)) left to a plan read. Two clauses. *One:* the accepted unit-row forms belong to the artifact, not to the backend that selected it. Inside the `superpowers` backend a plan under `docs/superpowers/plans/` reads `### Task <n>:` headings only, while the fallback `features/<f>/plan.md` reads its `| Unit | Status |` table or `### <f>/<n>` headings; the two are not interchangeable spellings of one grammar. A diagnostic names the layer it read and only that artifact's forms — naming a form the owning layer rejects sends the reader to a shape the parser will refuse. *Two:* a plan that exists and parses to zero unit rows is an **empty success** — exit 0, `rows: []`, the hint on stderr — not a finding. "No rows" and "unreadable" stay distinguishable by exit code: a missing artifact is a lookup miss at exit 1 naming both candidate roots, and an artifact that cannot be read is exit 1; only a readable artifact with nothing in it is exit 0. Empty is a fact about the work not yet broken down, and a query that refused it would make every freshly written plan unreadable until its first unit exists.
