# Feature: Review Hardening — Architecture

A port of the pre-v0.4 review-hardening fixes onto the v0.4 tree, plus fixes for
the v0.4 code that the old work never saw. No new subsystem. Everything lives in
the JS/bash harness that users run today. The Rust crates are untouched except
for one optional test. Old fixes come from the tag `rh-on-54e5983`, diffed
against its base `5ccb99b`. Entries marked **our call** are decisions made
without the owner.

## Changed-path scans use NUL output scoped to the project
Every hook that judges "what changed" runs `git -C <root> rev-parse --is-inside-work-tree --show-prefix`, then `git -C <root> status --porcelain -z -uall -- .`. It parses records by NUL, consumes the origin field of an `R` or `C` record, strips the prefix, and drops entries outside it. Porcelain v1 paths are toplevel-relative, so a scan without the prefix strip misses every change in a nested project. A stat error other than `ENOENT` or `ENOTDIR` blocks (fail closed). Bash reads `-z` output through process substitution and `read -r -d ''`, never through `$(...)`, which drops NULs.
<!-- /merge -->

## Content confinement is physical, not lexical
`confinePath` stays as the cheap lexical pre-check. `confineRealWhy(base, rel, {forWrite})` is the capability gate. It runs `realpathSync` on both the anchor and the target (macOS `/tmp` is `/private/tmp`), then a separator-aware prefix test. In-repo symlinks are allowed. For a missing write target it resolves the deepest existing ancestor. A dangling write link is refused. Every config-named or walked read goes through it: `walkMarkdown`, `loadBlocksDir` (shipped and `.vibe/blocks`), `applyConfigBlocks`, both reads in `lessonsFor`, and `render`'s `writeTarget`. A refusal is reported, never skipped silently. The frozen JS oracles keep the lexical behaviour, and the Rust port (F11) must pin these cases as expected divergences.
