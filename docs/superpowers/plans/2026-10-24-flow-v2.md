# flow v2 — Implementation Plan (Track 0–2: F5–F8, F11, v0.4 completion)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (recommended) or superpowers:executing-plans, task-by-task in the order below. Steps use checkbox (`- [ ]`) syntax. Cite the task id in commits and tests.

**Goal:** Rebase the flow half on the Rust `vibe-flow` CLI (F5–F8), rewrite the shipped skills terse and unambiguous (skills v2), route every flow surface through the post-v0.4 spec tree, adopt GSD compatibility additively, un-hold and build `vibe-instruct` (F11) in parallel, and sequence the remaining v0.4 rows to done. All state saves inside the repo.

**Architecture:** One `crates/vibe-flow` binary whose modules mirror the frozen oracles, with `machine::check_transition` as the single enforcement point; one `crates/vibe-instruct` crate porting the injection engine (channels/blocks/budgets) with the marker grammar shared via `vibe-core`; a five-tier POSIX `flow/bin/hook.sh` shim that never wedges a session; skills v2 as a single `SKILL.md` shipped to `.agents/flow`; runtime under `.vibe/run/`; a generation-2 oracle freeze as the last Track 0 commit; `vibe-parity` extended additively with a new flow suite over a generated corpus, teeth as pure-Rust negative tests with machine-derived counts.

**Tech Stack:** Rust 1.88 / edition 2024 (workspace deps unchanged: `vibe-core`, `clap`, `serde_json`), POSIX sh (shim), bash 3.2-safe test scripts, Node ≥20.19 (js-oracle parity legs only), JSON/Markdown data.

**Spec:** `docs/superpowers/specs/2026-10-24-flow-v2-design.md`. Issues: #25–#28 (F5–F8, in flight), #29–#32 (F12–F15), #38–#41 (F21–F24); F11 to file. Rulings FV-R1..R11 in the design are binding.
